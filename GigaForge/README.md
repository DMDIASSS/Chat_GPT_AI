# GigaForge native trainer — source preview

This is a new experiment, using the pinned public GigaLearn C++ simulator and trainer. Two independent policies: Chronos on Breakout, Galactus V2 on Octane. It starts from the original published split actors. Existing Fusion, selector and ForgeLeague models remain separate; their residuals and optimizer states cannot be silently transplanted into these native actors.

Status: compiled and checked on Linux CPU. Windows compilation and the CPU-built executable's CUDA-wheel compatibility require separate validation. Do not start a five-hour unattended run from this source preview. No Windows executable is bundled yet. The setup BATs require a verified native build or release metadata, and stop explicitly if missing.

## Source build

Use Python 3.11 with NovaForge requirements and PyTorch 2.9.1. On Windows install Visual Studio 2022 C++ Build Tools. Run `python tools/build_native.py`. The builder downloads an archive pinned by commit and SHA256, applies reviewed patches and builds Release C++. The source is https://github.com/ZealanL/GigaLearnCPP-Leak at 86e11c3881a21225a43c36b14af40f0b3c87e7dd. Credit Zealan and the original GigaLearn, RLGymCPP, RocketSim and Bullet authors. Source licenses/notices remain in the downloaded source; original actor notices remain beside fetched actors. GigaLearn is linked statically to avoid private-symbol DLL export issues. PyTorch runtime must match 2.9.1.

After a build, run `python run.py verify --device cpu`, then `python tests/check_native.py`. These check feature/mask/action-table/logit parity and actual warmup, actor learning, optimizer resume and batched paired evaluation. CUDA verification must run on the target GPU; Linux CPU success does not establish CUDA compatibility.

## Learning and throughput

The complete original networks are retained. FP32, two PPO epochs, optimizer batch 256, microbatch 256, gamma .999, lambda .97, actor LR .000005, critic LR .0003 and clip .05. First iteration trains the fresh critic while freezing actor and shared trunk. The original actor provides a .2 KL anchor, target PPO KL .015 and a .08 post-update anchor guard. Native terminal and multiple-timeout advantage bootstrap bugs are patched and checked. Policy and value share one equivalent trunk forward per training microbatch.

Reward is `10 * goal_outcome + .999 * Phi(next) - Phi(previous)`, where Phi is `.35 * team_relative_ball_y/5120 - .1 * min(car_ball_distance,12000)/6000`. Potential becomes zero at a goal. Training trajectories truncate and bootstrap after 60 seconds; first-goal reward differs from the Python ForgeLeague timed-match objective. No claim of guaranteed good play is made. Match strength is measured separately in timed multi-goal WDL.

`2_BENCHMARK.bat` sweeps simulation batch/thread counts, then measures full PPO on shortlisted settings with 1/2/4 Torch threads. It ranks useful samples per wall second, preserves epochs/model size/optimizer batch, and includes actor updates. This may take several minutes. Collection decisions count player actions, not 120 Hz physics frames. Only learner decisions count during frozen-opponent training. Normal logs show collection, used samples, optimizer steps, full update speed and end-to-end speed including process/model loading and saving. Laptop speed cannot be inferred from cloud CPU measurements.

Once all verification passes, `3_START_OR_RESUME` alternates blocks of frozen cross-family opponents, retained-parent opponents and current/history self-play. Only one trainer runs at once. Each family block targets 32768 new learner decisions, rounded to complete native rollouts/trajectories. Both teams are represented during cross play. Evaluations compare candidate and protected retained champion on paired seeds/colors against original Chronos/Galactus. Confirmation uses fresh seeds; uncertain candidates do not replace champions. Significant paired regressions or excessive anchor drift halt the experiment. The small default screen is conservative and noisy; a lack of promotion does not prove equal strength. No broad improvement has been established yet.

`4_PAUSE` requests a stop after the current update and complete checkpoint. Ctrl+C also waits safely; do not kill the console during save. Checkpoints include all three optimizers and counters, with staging and completion markers. Configs, hashes, provenance and metrics are saved under runs. Native RNG/physics trajectories are not promised bitwise reproducible, particularly demo respawns.

`5_WATCH_CHRONOS_BREAKOUT` and `6_WATCH_GALACTUS_OCTANE` watch protected champions. Candidate launchers are 10/11. The viewer receives actual hitbox configuration; a generic viewer mesh alone does not identify a model. Console labels identify learner and opponent. `7_EXPORT_RETAINED_BOTH_V5` produces separate complete TorchScript .lt/.pt actors plus v5 TOML, loadout and loader; import bot.bot.toml on this PC. The exported .pt and .lt are identical full actors, distinct from native POLICY.lt/SHARED_HEAD.lt shards. No unverified candidate silently replaces an export. `8_REPORT` packages diagnostics without weights or keys. W&B uses the existing login through the Python SDK, without searching arbitrary PC files for secrets.

The native engine bundles RocketSim 2.1.1, while the Python viewer/live feature adapter uses RocketSim 2.2.1. Feature parity is verified against controlled fixtures; exact physics and live strength require further measurement. Both contracts are 1v1; no new team hivemind is provided here.

## Short measured CPU check

Three full PPO iterations per family, 32 parallel games, original networks, frozen cross-family opponents, 8192 target training samples per iteration, batch/microbatch 256, two epochs, FP32, Torch threads 1. Chronos: 29696 learner decisions in 31.96 s (929/s), 24946 completed trajectory samples (781/s), 128 actor optimizer steps after warmup. Galactus: 30976 decisions in 35.10 s (882/s), 25211 completed samples (718/s), 128 actor optimizer steps. Collection-only rates within those updates ranged roughly 1700–3100/s. End-to-end times include startup/model loading, but this no-save benchmark excludes checkpoint writes, WDL and export. This is a cloud CPU smoke benchmark, not the user's laptop or a learning-strength experiment, and not a measured comparison with the previous Python trainer. Longer, repeated hardware tuning and actual WDL are still needed.
