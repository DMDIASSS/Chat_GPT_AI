# v0.1.6: replay shot catalog (read-only)

The goal-tail audit established that short replay shots can physically reproduce. HOWEVER the original training script uses a long-clip goal gate and stops at the last reference frame (before RocketSim's goal trigger), so no PPO training should run yet.

This tool filters **verified** 0.5- or 1.0-second windows from a completed v0.1.5 JSON audit. Both modes (ghosted, all_dynamic) must match the entire reference flight within the audit threshold and score with the replay-inferred actions by the deadline. It reopens the corresponding .npz snapshots, verifies schema and replay SHA, computes defender distances from ball, groups candidates into replay-level train/validation/test splits, and writes a JSON catalog. Distance is an opportunity heuristic, **not** a physical reachability prediction.

The next engineering phase is to implement a short-window, tail-aware PPO environment using this catalog, require defender counterfactual baselines, then run low-risk research PPO in an isolated candidate path. Do not repurpose the original full-clip `train_scenarios.py` as-is.

```bat

.venv\Scripts\python.exe -m slater_research.goal_tail_audit --clips data\replay_scenarios_smoke_v012 --limit 100 --windows 0.5,1 --post-seconds 0.3 --out data\replay_scenarios_smoke_v012\goal_tail_full_v015.json
.venv\Scripts\python.exe -m slater_research.scenario_gate --clips data\replay_scenarios_smoke_v012 --report data\replay_scenarios_smoke_v012\goal_tail_full_v015.json --out data\replay_scenarios_smoke_v012\shot_catalog_v016.json
```

If a report filename already exists, choose a NEW filename rather than overwriting it. Neither command edits original clips, PPO code, model checkpoints, AutoLeague, or the champion. `--limit 100` covers the 71 clips generated by the earlier 10-replay smoke extraction, not the entire full replay collection.
