# Nexto-based competitive curriculum: what is and isn't transferable

The previous AFK models `Cycle 9`, `Wavedash` and `best_verified.pt` use a native Nexto **attention actor** with `(q,kv,mask)` observation tensors and 90 actions. GigaLearn Research Hub uses **AdvancedObs**, `DefaultAction` and a distinct shared MLP head / actor. Reading `.pt` as `.lt` or averaging weights would not convert it. Both model architectures' inference must be validated independently.

## Required for a genuinely complete ordered curriculum

- **TAS gate:** Recover and document `.data` bitfield semantics and analog axes, initial RocketSim ball/car states, simulation version, controls at each 120 Hz tick. Run an open-loop replay and quantify divergence of positions/velocities across each frame. Only accept trajectories below a measured error threshold, then convert to native GigaLearn obs/actions with heldout-by-trajectory splits. Never use mere count of TAS frames as evidence of valid training examples.
- **Opponent gate:** Implement frozen Nexto/Cycle9/Wavedash inference in the *same* controlled RocketSim environment, including exact Nexto obs builder / action maps, previous actions, team inversion, reset rules, kickoff variants, correct 120 Hz controls, side swaps, checksums and frozen weights. Bench-test original Nexto against itself before using as teacher; verify both models act and produce nonzero touches before enabling PPO against teacher. This has not been achieved by the current GigaLearn C++ add-on.
- **Behavior safety gate:** Start with action-validity, touch and shot metrics against random and grounded starts, not only first-goal outcomes. Verify deterministic and stochastic inference. Report completed five-minute game results before calling win rates full-game percentages.
- **Mechanics:** Use separate fine-tunes for wavedash, wall dash, recovery, realistic air control, fast accurate shot, bump-after-shot, controlled dribble, smart flick timing and defensive shadow saves. Time-shift sample mechanics setups. Require usefulness against defenders and penalties for boost misuse and own goals.
- **Multiplayer:** GigaLearn's `AdvancedObs` dimensions scale with player count, so 1v1 checkpoint must not be copied into 1v2/3v3 unchanged. Architect padded/set-attention or transfer student in a supervised stage first; train 2v2/3v3, 1v2, 1v3, 2v3, 3v1 only after validation. Distinguish policy-controlled bots from truly frozen Nextos.
- **Evolution:** 12–24 isolated hyperparameter branches, paired seeds with swapped sides; screen then round-robin finalists against holdouts. Preserve offense and defense specialists; never select winners by training reward or short all-draw tournaments.
- **Operational:** Reduce automatic checkpoint frequency, add duplicate caching and resume for replay parsing, host separate bounded workers on the 4 GB GTX1650, GUI error reporting, protected trash, RLBot exporter for new `.lt` model (native Nexto v4 exporter cannot load GigaLearn `POLICY.lt`), watchable gameplay and rollback.

Until each gate passes, **the GUI must not claim that Nexto-based, TAS-trained or multiplayer-transfer versions exist**. All experiment weights must stay isolated and verification read-only.
